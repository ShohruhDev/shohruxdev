# Web / Mobile

Сайт Burxonov Shohrux для заказов на веб- и мобильную разработку в Узбекистане и СНГ. Nuxt 4 / Vue 3 / TypeScript / SQLite, SSR. Светлый авторский дизайн: мятная палитра, крупная типографика, объёмная иллюстрация и анимация плакатов при прокрутке.

Работают страницы услуг, журнал, форма обращения, закрытая редакция, календарь публикаций, worker подготовки материалов и источники заявок. Публичный предпросмотр размещён на Railway: https://web-production-0506cb.up.railway.app. HTTPS и постоянный том подключены. Собственный домен, API-ключ/модель, уведомления владельцу и CRM пока не подключены. Индексация отключена до подготовки настоящих публикаций. Ключи и зависимости в архив не включаются.

## Два языка

Публичный сайт работает на русском и узбекском (латиница). Русские адреса сохранены; узбекские начинаются с `/uz`. Переключатель RU / UZ открывает соответствующую страницу, сохраняя параметры выбора услуги. У страниц свои canonical, `lang` и взаимные hreflang. В RSS узбекская версия доступна по `/feed.xml?lang=uz`; sitemap включает только существующие опубликованные версии.

В редакторе статьи добавлен раздел узбекского перевода: заголовок, описание, короткий ответ, разделы, FAQ и источники. Интерфейс закрытой редакции остаётся русским. Оба языка хранятся в одной записи и публикуются по общему расписанию. Статья без перевода не появляется в узбекском журнале; её переключатель ведёт в узбекский журнал, а отсутствующий адрес возвращает 404.

Генератор настроен готовить две полные версии после исследования источников. Перед планированием двуязычной статьи нужна отдельная отметка о проверке перевода. Две версии увеличивают объём ответа и стоимость будущих API-запусков; реальный API пока не подключён. Стартовый черновик и три демонстрационные статьи переведены. Демонстрационные статьи доступны только в локальном preview, не в индексируемой production-сборке.

## Редакция и автоматизация

Подробнее о каналах, AI Search и рабочем процессе: [traffic-and-editorial.md](docs/traffic-and-editorial.md).

### Локальный запуск редакции

Используйте Node 24.15+ (проверено 24.22.1), откройте терминал в папке проекта:

```sh
npm install
npm run build
npm run editorial -- seed
npm run content -- import content/launch-brief-draft.json
npm run preview:local
```

Импорт черновика выполняется один раз; повторный импорт того же URL будет отклонён. В текущей локальной базе уже есть стартовые темы и этот черновик.

Откройте http://127.0.0.1:3000/admin и нажмите «Открыть локальную редакцию». Такой вход возможен только при явном ADMIN_LOCAL_PREVIEW=true, выключенной индексации и реальном loopback-адресе. `preview:local` предназначен исключительно для локального просмотра, не для публичного сервера. На этом Mac при несовместимом системном Node добавьте в PATH путь `/Users/macbookpro/Documents/Codex/2026-10-25/new-chat/work/runtime/node_modules/node/bin` перед командами npm. Этот вспомогательный runtime не входит в ZIP.

### Подключение на сервере

1. Долгоживущий Node-сервер, постоянный диск для SQLite, HTTPS reverse proxy. Не использовать эфемерный/serverless диск. SQLite рассчитана на один сервер; несколько процессов на том же диске координируют захват генерации через транзакции.
2. Создать `.env` из `.env.example`, права 0600. `SITE_URL=https://ваш-домен`, `SITE_INDEXABLE=true`, `CONTENT_DB` — абсолютный путь постоянной базы. После изменения SITE_URL/индексации пересобрать сайт. Не считать доступность локального URL публикацией в интернете.
3. `ADMIN_LOCAL_PREVIEW=false`. Задать случайный `ADMIN_PASSWORD` минимум 16 символов и `ADMIN_SESSION_SECRET` минимум 32 символа. Пароль хранится только в окружении; клиенту не выдаётся. Сессия HttpOnly/SameSite=Strict, на production Secure, срок 8 часов. После смены секрета перезапустить процесс: старые сессии перестанут работать. Для отзыва всех сессий менять секрет. Нужен HTTPS — Secure cookie не работает на обычном HTTP.
4. Указать `OPENAI_API_KEY` для отдельного API-проекта и `CONTENT_MODEL` с поддержкой Responses web_search и Structured Outputs. Модель пока намеренно не выбрана: бюджет владельца неизвестен. Установить денежный бюджет/ограничения проекта у провайдера. `CONTENT_MONTHLY_RUN_LIMIT=30` — число запусков, а не долларовый потолок. Проверить один реальный вызов после подключения; пока проверен только контракт на тестовом транспорте.
5. `CONTENT_AUTHOR=Burxonov Shohrux`. Установить `CONTENT_AUTOMATION_ENABLED=true`. Worker раз в минуту выпускает согласованные статьи, после 08:00 Asia/Tashkent готовит одну тему. Затраты на генерацию появляются только при настроенных ключе и модели; публикация проверенных материалов не требует ИИ.
6. Запускать `node --env-file=.env .output/server/index.mjs` под systemd/другим менеджером процессов, с рабочей директорией проекта. Обеспечить автоматический рестарт, постоянный доступ к диску, резервные копии SQLite и тест восстановления. Домен/HTTPS/деплой пока не настроены.
7. Настроить proxy body limit 200 KB для панели и 30 KB для заявок. Proxy должен передавать корректный Host и удалять поддельные forwarding-заголовки. Включать TRUST_PROXY только за доверенным proxy; иначе защита по IP может быть обойдена. API сравнивает Origin с фактическим URL запроса. Отключить кеширование `/admin` и `/api/**` на CDN; не блокировать поисковых роботов на публичных страницах.
8. Войти в /admin, проверить статью, сохранить и запланировать. На сервере проверить heartbeat, журнал запусков, публичный URL, RSS и sitemap. Короткий текст или отсутствие источников не пройдут проверку для календаря.

Не запускайте одновременно дополнительную cron-генерацию и встроенный worker без необходимости. Если используете внешний scheduler, оставьте CONTENT_AUTOMATION_ENABLED=false и выполняйте `npm run editorial -- tick` ежедневно после 08:00 Ташкента; для точного времени выпуска запускайте `npm run content -- publish-due` каждую минуту. Команда tick запускает подготовку независимо от часа, но соблюдает дневной/месячный лимит. Сами задания cron здесь не установлены. После простоя все просроченные согласованные статьи выпускаются при следующем проходе.

### Что доступно в панели

Материалы → редактор, предпросмотр, источники, FAQ, автор, короткий ответ. Сохранение сбрасывает расписание. Проверки редактора и слот времени → календарь. Версия материала проверяется сервером: устаревшая вкладка не может затереть новые правки или согласовать текст, который вы не видели. Во время сохранения поля и переключения панели блокируются.

Темы → 12 стартовых гипотез, добавление, пауза/возврат в очередь. Подготовка берёт первую активную тему. Ошибка сохраняется и расходует лимит дня; вернуть неудачную тему в очередь можно вручную. Лимит не гарантирует точный счёт API: тайм-аут может произойти после того, как провайдер начал платную работу.

Каналы и заявки → данные обращений, группы источников, UTM-ссылка. Это не счётчик всех посетителей. В публичную API данные обращений не выдаются. Отдельных внешних аналитических скриптов нет. Продажи, оплаты, CRM и уведомления о новых обращениях пока не интегрированы; оператор проверяет панель.

### Проверки новой версии

```sh
npm test
npm run typecheck
npm run build
npm run test:integration
npm run test:admin
npm run test:bilingual
```

HTTP-тесты используют отдельные временные базы и порты 3176/3177/3179. Генерация в тестах не вызывает реальный API. Исходники, .env.example, тексты и инструкции входят в архив; база, .env, зависимости, сборка и секреты исключаются.

## Дополнительно

Для разработки: `npm run dev`. База по умолчанию `.data/content.sqlite`; `CONTENT_DB` переопределяет путь. `npm run content -- leads` выводит личные данные заявок: используйте только в доверенном терминале. `npm run content -- list` показывает очередь. Управление и согласование материалов предпочтительно выполнять в /admin; старый CLI approve остаётся доверенным локальным инструментом ручного согласования импортированного JSON и не заменяет редакционную проверку.

Перед реальным приёмом заявок нужны контакты владельца, адаптация /privacy к фактической обработке данных, срокам хранения и применимым условиям, проверенные уведомления и проверка восстановления базы. База не шифруется приложением; защита диска и резервных копий относится к инфраструктуре. Не вводите реальные персональные данные в тестовый экземпляр.

Новый Git-репозиторий не создавался. Перед созданием ветки в подключённом репозитории обязательно `git fetch origin master`, затем ветка от свежего `origin/master`, как потребовал владелец.

Проверка публичного режима отдельно (только тестовый домен, не деплой):

```sh
SITE_URL=https://qa.web-mobile.test SITE_INDEXABLE=true npm run build
node tests/public.integration.mjs
# После проверки вернуть стандартную preview-сборку:
SITE_URL=http://127.0.0.1:3000 SITE_INDEXABLE=false npm run build
```

Тест запускает реальный worker на порту 3178 с временной базой; проверяет автоматический выпуск, доступность SSR/robots/sitemap/RSS и закрытость черновиков. Ни одна из этих проверок не отправляет платные запросы.
