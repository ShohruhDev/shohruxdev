# Web / Mobile — спецификация первой версии

Рынок: Узбекистан и русскоязычные заказчики СНГ. Исполнитель — независимый разработчик веб- и мобильных продуктов. Цель — качественные обращения и оплаченные проекты. Пользователь выбрал тёмную графитовую композицию с лаймовыми акцентами и разрешил разработку. Визуальный источник: exec-1f964264-d99f-4b5c-bce1-3f22ba7a8e39.png.

## Подход
Vue 3 + Nuxt с серверным HTML и TypeScript. Рассмотрены SPA (менее удобный исходный HTML для поисковых роботов), статический Nuxt с внешней CMS (дополнительный сервис для публикации) и Nuxt с серверной частью. Выбран последний как рабочее техническое решение для форм и редакционной очереди. Пользователь задал Vue, остальные решения приняты исполнителем.

## Объём
Главная, каталог и три страницы услуг, журнал с фильтрацией и статьями, процесс, контактная форма, политика обработки данных как черновик для адаптации. Исходные демонстрационные статьи явно отмечены. Настоящие кейсы и сведения о владельце не выдумываются.

Заявка: имя, контакт, задача, направление, необязательный бюджет, согласие. Сервер проверяет поля, ограничивает частоту и сохраняет данные локально в SQLite. Успех показывается только после сохранения. Никакие сообщения внешним адресатам не отправляются.

Редакционная очередь: draft → approved → published. CLI импортирует JSON, одобряет, назначает время и публикует только одобренные, наступившие по времени записи. SQL-транзакция защищает повторный запуск. Без API-ключей генерация новых статей не запускается. Ежедневная автоматика готовится как серверный cron, но не устанавливается на компьютер пользователя.

SEO: HTML SSR, title/description/canonical, sitemap только публичных страниц, Article/Breadcrumb JSON-LD, robots запрещает индексацию предпросмотра. При SITE_INDEXABLE=true разрешение доступно только с реальным HTTPS SITE_URL. Неизвестные slug → 404. Админка не публикуется: заявки и очередь доступны через локальный CLI, чтобы не создавать слабую авторизацию.

## Вне первой версии
Публичный деплой, покупка домена, настоящие контактные данные, интеграции уведомлений, LLM-генерация по платному API, узбекские переводы и реальное портфолио. Эти подключения описаны в плане запуска. SQLite рассчитан на один сервер с постоянным диском; масштабирование — переход к PostgreSQL. Готовность к коммерческому запуску не заявляется до подключения владельца, инфраструктуры и проверки условий обработки данных.

## Критерии
Рабочая навигация/форма/фильтры; сохранение заявки; защита черновиков и будущих публикаций; корректный 404; сборка и типизация; проверка desktop/mobile; отсутствие выдуманных доказательств и неработающих CTA.
