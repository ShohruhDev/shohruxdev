# Карта UTM-меток и источников (ноябрь 2026)

Дата: 16 ноября 2026. Задача T-004. Единые ссылки по каналам из `docs/promotion-plan-2026-11.md` и `docs/social-strategy-2026-12.md`. База: `https://razrabotkatashkent.uz` (`brandDomain` в `shared/brand.mjs`). Для узбекской аудитории путь с префиксом `/uz`, например `/uz/prices`. LinkedIn отложен, меток для него нет. Рекламу и любые траты запускаем только после одобрения владельца.

## 1. Правила меток

1. Только латиница нижнего регистра, цифры, `.`, `_`, `-`. Сервер удаляет всё остальное (пробелы, кириллицу, `+`) и обрезает значение до 100 символов.
2. Параметры: `utm_source` (площадка), `utm_medium` (тип), `utm_campaign` (формат или материал), `utm_content` (id поста, сторис, объявления).
3. Сайт запоминает метки только на первой странице визита. Ссылка без меток из приложений Instagram и Telegram часто выглядит как прямой заход, поэтому без меток ссылки не публикуем.
4. Ссылки собирать генератором в `/admin` → «Каналы и заявки». В нём нет поля `utm_content`: добавляйте `&utm_content=<id>` вручную в конец.
5. Значение `utm_source` определяет группу в `/admin` (раздел 3). Новые источники заводим только через эту таблицу, чтобы не плодить варианты.

## 3. Что реально сохраняется и как группируется

Заявка (`/contact`) сохраняет `source`, `medium`, `campaign`, `landing` (путь без query), `referrer` (хост) и вычисленную группу `channel`. `utm_content` не сохраняется нигде, его видно только в Яндекс Метрике.

Группа в `/admin` вычисляется по `utm_source` (если пуст, по хосту реферера), затем по `utm_medium`:

| Условие                                                                    | Группа в `/admin`  |
| -------------------------------------------------------------------------- | ------------------ |
| source: chatgpt, perplexity, claude, gemini или хосты этих сервисов        | ИИ-поиск           |
| medium: `cpc`, `ppc`, `paid`                                               | Реклама            |
| source или реферер: `google.*`, `bing.com`, `yandex.*`                     | Поисковики         |
| source: `telegram`, `instagram`, `facebook`, `youtube`, `vc`, `habr`, `t.me` | Соцсети          |
| любой другой source или реферер                                            | Другие сайты       |
| пусто                                                                      | Прямые / неизвестно |

Что это значит для карты в разделе 2:

- Telegram, Instagram, Facebook попадают в «Соцсети».
- `vcru`, `workspace`, `freeuz`, `olx`, `google`, `yandex`, `2gis`, `email`, `spotuz` и др. попадают в «Другие сайты». Различать их нужно по `source` и `campaign`: в Telegram-уведомлении они видны, в списке заявок `/admin` видны только группа, `landing` и `campaign`.
- `utm_source=google` или `yandex` без домена (`google.com`) не считается «Поисковиками». Это нормально: карточки карт и органика различаются.

## 4. Вопрос «Откуда вы о нас узнали?»

В форме `/contact` такого поля сейчас нет, сервер его не принимает (см. раздел 5). Пока задаём вопрос сами: в первом ответе в Telegram, в начале звонка, в письме с КП. Ответ записываем в таблицу обращений (дата, источник, что нужно, итог), как описано в `docs/social-strategy-2026-12.md`.

RU:

```text
Подскажите, пожалуйста, откуда вы о нас узнали? Нам важно понимать, какие каналы работают.
```

UZ:

```text
Iltimos, biz haqimizda qayerdan bilib oldingiz? Qaysi kanallar ishlayotganini bilish biz uchun muhim.
```

Варианты ответа для таблицы (единые значения):

| Значение в таблице | Что это                                           | Соответствует метке                  |
| ------------------ | ------------------------------------------------- | ------------------------------------ |
| `search`           | нашёл в Google или Яндексе                        | органика, группа «Поисковики»        |
| `maps`             | карточка Google, Яндекс Карты или 2GIS            | `google`, `yandex`, `2gis` (organic) |
| `telegram-channel` | канал @razrabotkatashkent                         | `telegram` / `channel`               |
| `telegram-chat`    | ответ в чате предпринимателей или IT              | `telegram` / `chats`                 |
| `instagram`        | профиль или сторис                                | `instagram`                          |
| `facebook`         | страница Facebook                                 | `facebook`                           |
| `article`          | vc.ru, журнал сайта, СМИ                          | `vcru`, `spotuz` и др. (article)     |
| `directory`        | Workspace.ru, Free.uz, OLX.uz                     | `workspace`, `freeuz`, `olx`         |
| `ai`               | ChatGPT, Perplexity и другие ИИ-ассистенты        | группа «ИИ-поиск»                    |
| `referral`         | рекомендация знакомого или клиента                | меток нет                            |
| `other` / `unknown`| другое или не помнит                              | меток нет                            |

Если заявка пришла с сайта, сверяйте ответ клиента с группой в `/admin`. Расхождение не ошибка: метка показывает последний переход, а человек помнит первое касание. В отчёте приводим оба значения.

## 5. Расхождения между схемой, кодом и существующими ссылками

Код не менялся. Пункты 1 и 2 требуют решения владельца (затрагивают `server/`).

1. **Нет поля «откуда узнали».** `app/pages/contact.vue` отправляет `name`, `contact`, `service`, `budget`, `message`, `consent`, `website` (ловушка для ботов) и `attribution`. `validateLead` в `server/lib/core.mjs` лишних полей не сохраняет. `docs/promotion-plan-2026-11.md` («В форме можно спросить, откуда клиент узнал о вас») описывает то, чего в форме пока нет. Предложение разработчику: необязательный select с значениями из раздела 4 и вывод в `server/lib/notify.mjs`.
2. **`utm_content` не сохраняется.** `app/plugins/attribution.client.ts` читает только `utm_source`, `utm_medium`, `utm_campaign`. В заявке и Telegram-уведомлении нет id поста, в Метрике есть. Разбивка заявок по постам без доработки невозможна.
3. **В списке заявок `/admin` не видны `source` и `medium`.** Показаны группа, `landing` и `campaign`. `source` виден в Telegram-уведомлении (`notify.mjs`: группа · source или referrer · campaign). `medium` не показывается нигде, хотя хранится. В `docs/social-strategy-2026-12.md` написано, что журнал хранит source, medium и campaign: хранит, но не показывает.
4. **Метки запоминаются один раз за сессию.** Если первая страница визита без меток, последующие метки в рамках сессии игнорируются (`sessionStorage`, ключ `arrival`). Пользователь, пришедший по ссылке без метки и потом по размеченной, будет «прямым».
5. **Генератор в `/admin` не имеет поля `utm_content`**, а `docs/social-strategy-2026-12.md` требует его для постов. По умолчанию генератор подставляет `telegram`, `social`, `journal`.
6. **Сторис: две схемы.** `docs/social-stories-2026-11.md` использует `utm_medium=story`, `utm_campaign=<ключ Highlight>`; `docs/social-strategy-2026-12.md` использует `utm_medium=social`, `utm_campaign=stories`. В этой карте принята вторая (единый `social`, как у остальных соцсетей). Страницы со старой схемой нужно привести к ней, иначе фильтр «UTM Medium = social» в Метрике потеряет часть сторис.
7. **vc.ru: `vcru`, а не `vc`.** `docs/vcru-article-2026-11.md` уже использует `utm_source=vcru&utm_medium=article`. В коде в «Соцсети» попадает только `vc` или `vc.*`, поэтому `vcru` идёт в «Другие сайты». Оставлено как есть: статья vc.ru ближе к внешней площадке, чем к соцсети.
8. **Существующие посты без `utm_content`.** `shared/telegram-posts.mjs` (10 постов, RU и UZ) и `fb-1…fb-6` в `shared/social-posts.mjs` размечены только `campaign=channel` или `campaign=posts`. `utm_content` (`fb-N`, id поста) появляется в декабрьском плане (fb-7 и далее, Telegram с `hidden-costs`). Для старых постов разбивка по Метрике невозможна, если их ссылки не менять.
9. **Telegram-ссылки в `docs/telegram-launch-2026-11.md`** предлагают `post-01…post-10` для `utm_content`, а декабрьский план использует осмысленные id (`hidden-costs`, `bilingual-site`). В этой карте принято правило «id поста из плана»; `post-NN` для первых десяти постов, если решим их размечать, не конфликтует.
10. **Карточки на картах.** `utm_source=google|yandex|2gis` с `utm_medium=organic` дают группу «Другие сайты», а не «Поисковики». Ссылки из `docs/business-listings.md` оставлены без изменений, чтобы не править карточки без нужды.
11. **LinkedIn.** Метки `utm_source=linkedin` остались в `docs/social-kit-2026-11.md` (разделы про LinkedIn) и в коде попадают в «Соцсети». Сеть отложена, ссылки не использовать.
12. **Instagram, лента.** В подписях постов ссылок нет («ссылка в профиле»), поэтому в ленте метки не нужны: работает метка профиля `campaign=profile`. Отличить пост, из которого человек пришёл, нельзя. Определить можно только по вопросу из раздела 4.
13. **`utm_source` в нижнем регистре, `utm_campaign` и `utm_content` сервер не приводит к нижнему регистру.** Чтобы отчёты не дробились, всегда пишем всё строчными.

## 6. Как проверять

- Перед публикацией открыть ссылку и убедиться, что страница открывается без ошибки.
- Метрика → «Источники» → «Метки UTM»: разбивка по `utm_source`, `utm_campaign`, `utm_content`; цели `lead`, `telegram_click`, `phone_click`, `calculator_cta`.
- `/admin` → «Каналы и заявки»: группы и последние заявки. Это число сохранённых заявок, а не посетителей.
- Таблица обращений: добавляем столбец «ответ на вопрос о источнике» из раздела 4. Раз в неделю сверяем с Метрикой и `/admin`. Выводы делаем только по фактическим заявкам, в первые недели выборка мала.
- Остановка: канал без визитов и обращений за 90 дней плана (`docs/promotion-plan-2026-11.md`) пересматриваем и не продлеваем. Решение за владельцем.
