# Подготовка размещения

Сайт размещён на Railway: см. [railway.md](railway.md). Ниже — альтернативные шаблоны для самостоятельного VPS; на VPS они не установлены. Собственный домен пока не подключён.

Нужен Linux VPS/долгоживущий Node-хостинг с Node 24.15+ и постоянным диском. Для текущего SQLite/worker проекта обычного статического хостинга недостаточно. Без данных о нагрузке сервер не подбирался и стоимость не оценивалась.

Пример расположения: приложение `/srv/web-mobile`, отдельный системный пользователь `web-mobile`, постоянные данные `/var/lib/web-mobile` с правами 0700 и владельцем `web-mobile`, приватные переменные `/etc/web-mobile.env` (root, 0600). `/usr/bin/node` в unit должен указывать на совместимый runtime, а не старую системную версию.

Порядок:

1. Выбрать домен, проверить доступность регистрации, оформить на владельца. Обеспечить доступ к DNS и восстановлению аккаунта.
2. Создать сервер/учётную запись хостинга. Подготовить пользователя, каталоги, постоянный диск и резервное копирование.
3. Скопировать исходники без `.data`, `.env`, `node_modules` и старой сборки. Установить зависимости `npm ci`.
4. Задать реальные SITE_URL и SITE_INDEXABLE=true в окружении сборки, выполнить `npm run build`. Не оставлять YOUR_DOMAIN и тестовый домен в публичной сборке.
5. Скопировать и заполнить server.env.example. Сгенерировать уникальный пароль и секрет; примеры значений нельзя использовать как пароль. Настроить API отдельно после определения бюджета. Секреты не добавлять в Git.
6. Установить web-mobile.service после проверки путей. systemd читает приватный EnvironmentFile, сервер слушает только 127.0.0.1:3000. `ProtectSystem` оставляет запись только в каталоге данных.
7. Настроить reverse proxy, DNS, HTTPS, правильный Host/proto, ограничения размера тела и соединений. Наружу открывать HTTPS, не порт Node. Проверить same-origin запросы и Secure cookie через настоящий домен.
8. Войти в редакцию, загрузить стартовые темы, проверить материалы и календарь. Ключ/модель без проверки не считать рабочими. Проверить один контролируемый запуск и расход в кабинете провайдера.
9. Проверить сайт/robots/sitemap/feed без авторизации. Добавить сайт в поисковые кабинеты. Проверить, что CDN не блокирует OAI-SearchBot на публичных страницах.
10. Проверить фактическую заявку, доступ владельца, уведомления и восстановление резервной копии. Политику данных адаптировать к реальным условиям до приёма персональных данных.

SQLite в WAL-режиме: обычное копирование только основного файла во время записи может дать неполную копию. Используйте согласованный механизм backup SQLite либо остановите процесс и копируйте согласованный набор файлов; восстановление проверяйте отдельно. Обновление кода не должно очищать CONTENT_DB.

Параметры инфраструктуры и доступы требуются для следующего этапа. Systemd unit проверен как шаблон, но не установлен и не запускался на Linux в этой сессии (разработка выполнялась на macOS).
